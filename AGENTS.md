# Règles de travail

- Après chaque modification demandée, effectuer les vérifications adaptées, créer un commit et pousser systématiquement vers le dépôt distant. Ne pas redemander confirmation pour ce push.
- Ne jamais versionner de données personnelles : fichiers de sauvegarde JSON, listes réelles de tâches ou de clients, contenu du navigateur, secrets. Le code publié doit démarrer avec des listes vides ; les tests utilisent des données fictives.
- Préserver les données locales et les changements existants. Si le push échoue, le signaler sans forcer ni réécrire l’historique.
